A-103 · Grasshopper

A façade shaped by
how much light it lets in.

A parametric brick screen where the geometry isn't drawn by hand — it's derived. A Python script node inside the Grasshopper definition analyzes daylight and lux levels across the façade, that analysis sets the window-to-wall ratio for each zone based on its function and light need, and the same values then drive every brick's rotation angle and opening size. Light input becomes masonry output.

Daylight / lux analysis (Python node)→WWR per façade zone→brick rotation + opening size→generated screen
Why derive it

The problem

A perforated brick screen is usually patterned by eye — an aesthetic choice repeated uniformly across a whole façade, regardless of which rooms sit behind which part of it, or how much daylight each one actually needs.

The approach

Run a lux / daylight analysis first. Let that analysis decide how open or closed each façade zone should be — its window-to-wall ratio — based on the function behind it. Then let every individual brick's rotation and opening follow that same number, so the pattern is a direct readout of the light behind it, not a decoration applied on top.

Pipeline

Three stages, one script node in the middle

01 · Analysis

Daylight & lux

A Python script node computes daylight / lux levels across the façade, zone by zone, as the definition's environmental input.

02 · Ratio

Window-to-wall ratio

Each zone's WWR is set from its lux reading together with the function behind that part of the façade — more opening where more daylight is needed, less where it isn't.

03 · Brick

Rotation + opening

The WWR and lux values are read back down to brick scale — each brick's rotation angle and opening size follow the same gradient, so the masonry pattern visibly tracks the light behind it.

What the definition is doing, in outline

lux_map = python_node.analyze(daylight_inputs) # per façade zone wwr = f(lux_map, zone_function) # more lux need → higher WWR for each brick in zone: brick.rotation = map(wwr, angle_min, angle_max) brick.opening = map(lux_map[zone], opening_min, opening_max)

Higher target daylight in a zone pushes its WWR up, which in turn opens the brick rotation and opening further in that region — and pulls both back down where the function behind the wall calls for less light or more privacy.

Reading the pattern

Light gradient, in brick

A schematic reading of the logic above — brick opening increasing from left to right as the target daylight rises across the façade. The generated definition produces the same gradient directly from the lux analysis, not from a manually drawn ramp.
